# Web data schema

Each record in `public/data/records.json` contains:

| Field | Purpose |
| --- | --- |
| `id` | Stable record identifier |
| `date` | Publication date in `YYYY-MM-DD` format |
| `year` | Year filter and aggregation |
| `semester` | Fall or Spring filter |
| `kind` | Dart, Pat, or combined entry |
| `text` | Full published text |
| `target` | Short parsed target when available |
| `sender` | Short parsed sender description when available |
| `sourcePdf` | Source PDF filename |
| `newspaperPage` | Printed newspaper page |
| `pdfPage` | Page within the source PDF |
| `positionOnPage` | Entry order on the page |

The source workbook columns omitted from the web file are either redundant with these fields, derivable from `date`, long parsing intermediates, or internal coding metadata.

## Analysis files

`public/data/enrichment.json` is keyed by the stable record `id` and adds:

| Field | Purpose |
| --- | --- |
| `primaryTopic` | Best match from the controlled topic vocabulary |
| `secondaryTopics` | Up to two additional plausible topic matches |
| `topicConfidence` | High, medium, low, or unclassified |
| `topicEvidence` | Dictionary terms supporting the primary match |
| `topicScores` | Reproducible scores for every matched topic |
| `entities` | Campus organizations, groups, and places found by the entity dictionary |

`public/data/analysis.json` contains topic, entity, and editorial-balance aggregates used by the visualizations.

These annotations are generated by `scripts/enrich_data.py`. They are a transparent first pass for exploration, not final human-coded research data. Formal analysis should validate the vocabulary and review low-confidence and unclassified records.
